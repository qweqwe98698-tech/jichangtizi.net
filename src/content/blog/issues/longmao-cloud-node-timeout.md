> **核心结论**：在 Clash Verge Rev 或 Shadowrocket 中看到龙猫云（LongMaoCloud）节点显示 **“Timeout（连接超时 / 报红）”**，其技术本质仅代表**客户端在指定时间阈值（通常为 2000ms~5000ms）内未能收到目标节点或测试服务器的握手回包**。
> 
> **技术定调与排查黄金法则**：
> - **Timeout 绝不等于跑路**：单节点维护、地区入口割接、旧订阅缓存、本地系统时间偏差、家庭宽带 DNS 污染或单纯的测速目标 URL 波动，都会表现为 Timeout；
> - **先定范围再动手**：先看是“单个节点超时”、“一个地区超时”还是“全站节点集体超时”；
> - **7 步快速处置闭环**：**右键 Update 更新订阅 ➔ 跨地区测备用节点 ➔ 切换 Wi-Fi/手机热点 ➔ 校准系统时间 ➔ 检查后台套餐 ➔ 查看客户端错误日志 ➔ 必要时联系官方工单**。
> 
> *声明：本文基于跨国网络传输与代理客户端调度机制提供客观排障指南，切勿因单次超时盲目重装系统或随意修改高级底层配置。*

## 二、深入本质：Timeout 到底是什么？不等于什么？

在排查前，必须理清网络底层的技术定义：

```
客户端发起连接 ───(发送 SYN 握手包)───> [网络路径 / 中转入口 / 节点服务器]
                                                 │
                                                 ▼ (超过指定超时时间仍未收到 ACK 回包)
客户端倒计时结束 ──────────────────────────> 触发「Timeout (连接超时)」
```

### 1. 导致 Timeout 的可能阶段：
- **DNS 解析超时**：客户端无法将节点的域名解析为真实服务器 IP；
- **TCP 连接超时**：本地宽带到国内入口机房、或中转到海外出口路段发生丢包；
- **TLS 握手超时**：本地系统时间误差过大或证书校验失败；
- **测试目标服务器超时**：节点本身正常，但客户端用来测速的 Google/Cloudflare 测试网址本身被本地网络阻断。

### 2. Timeout 坚决不等于什么：
- ❌ **不等于服务商跑路**；
- ❌ **不等于你的套餐一定过期**；
- ❌ **不等于该节点被永久封禁**；
- ❌ **不等于你的电脑客户端彻底损坏**。

## 三、常见错误类型与含义深度对照表

不要把客户端里的所有红字都统称为“节点挂了”，学会辨析具体的错误提示：

| 错误代码 / 提示 | 大致技术含义 | 核心根源定位 | 优先排查与修复方向 |
| :--- | :--- | :--- | :--- |
| **Timeout (连接超时)** | 在规定时间内未收到服务器回包 | 单机维护、线路拥塞、旧 IP 失效、时间误差 | **Update 订阅、校准系统时间、切换备用节点** |
| **Connection Refused (拒绝连接)**| 目标服务器在线，但端口未监听 | 节点后端服务重启、端口参数被服务商变更 | **右键更新订阅配置以获取最新端口** |
| **Network Unreachable (网络不可达)**| 本地网关或路由表无法找到出口 | 本地电脑断网、路由器故障、网卡冲突 | **检查本地宽带、重启家用光猫与 Wi-Fi** |
| **DNS Error / lookup failed** | 无法将节点域名解析为 IP 地址 | 本地 DNS 污染、路由器拦截 DNS 请求 | **将本地 DNS 修改为 `223.5.5.5` 或换手机热点** |
| **TLS / Certificate Error** | TLS 安全加密握手或证书校验失败 | **本地系统时间与国际标准时间存在偏差** | **进入系统设置点击「立即同步时间」** |
| **Authentication Error (403/认证失败)**| 用户身份鉴权 Token 未通过校验 | 套餐到期停机、超额流量耗尽、Token 被重置 | **登录后台检查套餐状态，重新导入最新订阅** |
| **Parse Error (配置解析失败)** | YAML 文件结构损坏或字段不兼容 | 订阅 URL 被拦截截断、客户端版本过旧 | **升级客户端版本，重新复制原生订阅 URL** |

## 四、故障范围分级判定：不同层级的 Timeout 怎么看？

### 1. 第一种情况：只有一个节点显示 Timeout
- **现象**：例如“香港01”报红，但“香港02”与“日本01”均正常全绿；
- **结论**：**龙猫云整体服务完全健康，本地客户端配置完全正确**；
- **处理**：直接点击使用“香港02”或“日本01”，无需折腾客户端，等待服务器自动维护完毕即可。

---

### 2. 第二种情况：同地区节点全部显示 Timeout
- **现象**：香港 01、02、03 节点全部超时，但日本、新加坡、美国节点测速正常且能秒开网页；
- **结论**：属于**该特定地区的入口机房网络割接、中转海缆维护或集中并发排队**；
- **处理**：临时将代理组切换至 **日本 (JP)** 或 **新加坡 (SG)** 节点，关注官方公告。

---

### 3. 第三种情况：所有国家大区全部节点集体报红 Timeout
- **现象**：香港、日本、美国、新加坡所有节点无一例外全部显示 Timeout；
- **结论**：**90% 属于本地系统环境、旧订阅缓存或套餐状态异常**，进入下方全流程系统排障。

## 五、核心排障第 1 梯队：订阅与套餐状态核验

### 第 1 步：为什么必须在 Profiles 强制 Update 龙猫云订阅？
很多用户误以为：“我在列表里能看到节点名字，说明配置就是对的。”

**这是严重的认知盲区！** 客户端会长期缓存上一次成功下载的本地配置文件。当服务商因机房维护更换了服务器 IP 或端口后，**客户端里显示的依然是失效的旧 IP 地址，测速必然 100% 全红超时！**

```
[Clash Verge Rev] 点击左侧「Profiles」➔ 找到龙猫云卡片 ➔ 右键点击「Update」
[Shadowrocket]    在首页龙猫云分组名称上 ➔ 向右滑动 ➔ 点击「更新」
```

---

### 第 2 步：登录后台核验套餐与流量余额
- 确认套餐是否已到达截止日期；
- 确认当期可用流量是否已被大文件下载消耗为 0；
- 确认是否超出了套餐允许的**同时在线设备数上限**。

---

## 六、核心排障第 2 梯队：网络环境与测试机制纠偏

### 第 3 步：切换本地网络环境（Wi-Fi vs 4G/5G 手机热点）
家庭宽带的路由器故障或本地运营商 DNS 污染是导致全红超时的隐形杀手：
- **测试方法**：手机关闭 Wi-Fi，打开 4G/5G 移动蜂窝网络，开启小火箭或将热点分享给电脑进行测试；
- **排障结论**：
  - 若手机热点下节点全部变绿且能正常打开网页 ➔ **说明龙猫云服务器完全正常，问题 100% 在家庭路由器或本地宽带运营商**；
  - 此时应重启家用光猫与路由器，并将路由器 DNS 改为 `223.5.5.5`。

---

### 第 4 步：打破迷思！为什么“测速显示 Timeout”却依然能正常打开网页？

很多新手看到列表里标红的 `Timeout` 就慌了，实际上**客户端内置的“延迟测试”与“真实访问网页”是两套完全不同的机制**：

| 测试方式 | 实际测试的是什么对象 | 为什么可能会误报 Timeout | 正确参考价值 |
| :--- | :--- | :--- | :--- |
| **客户端延迟测试 (URL-Test)** | 向单个固定地址（如 `gstatic.com`）发送探测请求 | 该测试 URL 刚好被本地运营商阻断或解析异常 | **仅供快速筛选，不能作为节点生死的绝对依据** |
| **真实浏览器访问网页** | 访问 Google、YouTube 实际业务服务器 | 业务服务器有多线 CDN 容灾 | **只要网页能秒开，红字 Timeout 完全可以忽略** |
| **ICMP Ping 丢包测试** | 向节点服务器发送 ICMP 底层探测包 | 很多高防机房主动禁 ping（丢弃 ICMP） | **禁 ping 节点的 ICMP 必为 100% 丢包，但代理端口完全正常** |

> 📌 **核心法则**：**“永远以真实浏览器能否打开网页为最终标准，切勿对着测速面板的红字死磕！”**

---

## 七、核心排障第 3 梯队：客户端、协议与系统环境排查

### 第 5 步：校准本地系统时间与时区（90% 全红根源）
- **致命影响**：跨国加密协议对本地时间戳校验极严。**本地电脑时间误差超过 60 秒，会导致所有节点握手被拒，瞬间全红 Timeout**；
- **修复**：在 Windows 设置中点击“立即同步时间”，或在 iPhone 设置中开启“自动设置时间”。

---

### 第 6 步：区分 DNS 解析超时 vs 节点连接超时
打开 Clash Verge Rev 的 **「日志 (Logs)」** 面板观察具体日志：
- 若日志包含 `lookup [domain] timeout` 或 `no such host` ➔ **DNS 故障**，切换本地 DNS 或换网络即可解决；
- 若日志显示 `dial tcp 123.45.67.89:443 timeout` ➔ 说明域名已成功解析为 IP，是**该具体 IP 端口暂时不可达**，更新订阅即可拉取新 IP。

---

### 第 7 步：排查多代理软件冲突与防火墙拦截
- 确认电脑没有同时运行 v2rayN、其他商业 VPN 或抓包软件导致本地端口冲突；
- 暂时退出第三方杀毒卫士，避免安全软件将本地代理监听端口误杀。

---

### 第 8 步：排查 TUN 虚拟网卡导致的路由回环
- 在 Clash Verge Rev 中，若开启 TUN 模式后节点测速全部变为 Timeout，通常是因为 TUN 虚拟网卡与本地安装的 Docker、VMware、Hyper-V 网卡产生了路由表冲突；
- **解决**：先关闭 TUN 模式，仅开启「系统代理」测试。
详细 TUN 机制对比参考：[《Clash TUN 模式和系统代理有什么区别？完整指南》](/wiki/clash-tun-mode-vs-system-proxy/)。

## 八、最核心的方法论：四维交叉定位矩阵

遇到疑难故障时，通过以下四维交叉测试，可在 2 分钟内精准定性：

| 交叉测试维度 | 测试表现与现象 | 100% 锁定的根源层级 | 终极修复方案 |
| :--- | :--- | :--- | :--- |
| **节点维度** | 仅香港 01 报红，香港 02 正常 | 🟢 **单节点维护 / 单机负载** | 手动切换至香港 02 正常使用 |
| **地区维度** | 香港全部报红，日本/美国全绿 | 🟡 **香港机房入口网络调整** | 临时将节点切至日本或美区 |
| **客户端维度** | 电脑 Clash 全红，手机小火箭全绿 | 🟢 **电脑本地客户端或系统问题** | 校准电脑时间，重启电脑网卡 |
| **网络环境** | 家里 Wi-Fi 全红，切 5G 手机热点全绿 | 🟢 **家庭路由器 / 本地宽带 ISP 故障** | 重启光猫与路由器，修改路由器 DNS |
| **全维度** | 手机、电脑、热点、全节点多天持续全红 | 🔴 **龙猫云服务端整体维护或订阅失效** | 登录后台确认套餐状态，联系客服支持 |

## 十一、什么时候属于服务端问题？什么时候才需考虑备用机场？

我们始终坚持客观中立的评测原则：**“只有当排除了所有本地变量后，才能归咎于服务端。”**

### 满足以下全部条件，才表明服务端正在经历重大调整：
1. 进行了**四维交叉测试**（手机 + 电脑 + 家庭宽带 + 5G 蜂窝数据均持续超时）；
2. 已在后台重新生成订阅链接并重新导入，依然无法拉取节点；
3. 官方公告栏发布了重大机房割接或上游网络故障通知。

> 💡 **备用机场核心价值**：没有任何一家机场能保证 365 天 100% 永无海缆波动。对于重度依赖跨境网络的生产力用户，**常备一个低成本的不限时流量包作为第二备用通道**，是抵御突发超时的终极解法。

## 十二、高频常见问题解答（FAQ）

### Q1：龙猫云节点显示 Timeout 是什么意思？
**答**：Timeout 表示客户端向该节点发送连接请求后，在规定时间内未收到服务器的回包。这通常是由于单机维护、旧订阅缓存未更新、系统时间偏差或本地网络阻断引起的，绝不等于服务商跑路。

### Q2：龙猫云所有节点突然全部报红超时怎么办？
**答**：首先在系统设置中**立即同步电脑/手机时间**；随后在 Profiles 中右键 Update 强制更新订阅以获取最新 IP；最后切换手机热点测试排除家庭路由器问题。

### Q3：为什么节点测速显示 Timeout，但实际上能正常打开 Google？
**答**：因为客户端内置的延迟测试只是向单个固定网址（如 `gstatic.com`）发包，若该测试网址被本地网络临时阻断就会显示 Timeout。只要真实网页能秒开，无需理会测速面板上的红字。

### Q4：为什么更新了订阅后节点依然全部超时？
**答**：请登录龙猫云后台核对套餐是否已到期停机，或者当期流量是否已被耗尽。若后台正常，请检查电脑是否开启了其他冲突的代理软件或虚拟机网卡。

### Q5：香港节点全部超时，但日本节点全绿正常是怎么回事？
**答**：这属于典型的地区机房维护或晚高峰入口网络波动。直接切换至日本或新加坡节点使用即可，无需修改本地配置。

### Q6：为什么手机连 Wi-Fi 节点全部超时，但切 4G 移动数据就正常？
**答**：这 100% 是家庭 Wi-Fi 路由器的问题（如路由器 DNS 污染或宽带光猫路由故障）。重启路由器光猫，并将路由器 DNS 手动改为 `223.5.5.5` 即可恢复。

### Q7：龙猫云节点 Timeout 是不是被 GFW 封锁了？
**答**：如果只是单个节点或单个地区超时，通常是常规机房维护；服务商具备自动动态轮换 IP 机制，右键 Update 更新订阅即可自动获取最新可用节点。

### Q8：节点全部超时多久才应该考虑启用备用机场？
**答**：若经过手机热点多端交叉测试均全红，且持续 2~3 小时官方未恢复，建议切换至备用机场应急，保障日常工作不中断。

## 总结与最终排障结论

> **Timeout 排障终极箴言**：
> 
> 1. **冷静定范围** ➔ 单节点切备用，单地区换国家，全站超时查本地与订阅；
> 2. **逢超时先校时** ➔ 本地系统时间差 1 分钟即可造成全站全红超时；
> 3. **以实测为准绳** ➔ 网页能秒开就是真正常，切勿为测速面板的红字焦虑！
