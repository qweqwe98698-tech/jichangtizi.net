> **核心结论**：在 Clash 或 Mihomo 客户端中能够看到节点列表，甚至测速显示正常的绿色延迟（如 35ms），**并不代表完整的代理数据链路一定可以正常上网**。
> 
> “有节点但无法上网”最常见的原因包括：**单节点已在服务端失效但探测包仍有微弱回包、系统代理开关未真正生效、代理模式误设为 Direct、订阅配置过期未同步、内置 DNS 解析死锁或污染、TUN 虚拟网卡与第三方 VPN 路由冲突，以及电脑系统时间不同步导致 TLS 握手被拒**。
> 
> 遇到故障时**切忌盲目频繁重装软件**。最有效的方法是遵循 **“本地裸网 ➔ 节点切换 ➔ 系统代理 ➔ 分流模式 ➔ DNS 解析 ➔ TUN/路由 ➔ 订阅与内核”** 的 7 步标准分层排查法，通常在 2 分钟内即可精准锁定问题根源。

## 二、为什么“节点有延迟”，浏览器却依然打不开网页？

这是无数新手最容易困惑的现象：
```
香港 IEPL 01    [ 32ms (绿色) ]
日本 IPLC 02    [ 45ms (绿色) ]
新加坡 01       [ 68ms (绿色) ]
```
明明全排节点都是漂亮的低延迟，为什么打开 Google、YouTube 却提示“无法访问此网站 / 响应时间过长”？

### 揭秘：延迟测试与实际网页访问的底层差异

1. **测速仅测试单一 HTTP 探测点的首包握手**：
   在 Clash / Mihomo 中，点击测速只是向 `http://www.gstatic.com/generate_204` 发送了一个极其微小的单包探测。只要该探测点有回包，就会显示绿色数字；**但这完全不能证明该节点能够成功解析并转发其他所有网站的 HTTPS 数据流**；
2. **流量根本没有真正进入 Clash**：
   节点是好的，但你的 Windows / macOS 系统代理开关未开启或被杀毒软件拦截，浏览器的请求依然在走本地直连，当然打不开被墙网站；
3. **DNS 解析阶段在本地被掐死**：
   浏览器访问 `www.google.com` 时，首先需要将域名解析为 IP。如果 Clash 内置 DNS 发生死锁，在发起 HTTP 连接前就已经报错崩溃；
4. **服务端出口 IP 被目标网站风控屏蔽**：
   节点与中转线路畅通，但海外落地机房 IP 被 Google / OpenAI 实施了精准拦截封锁。

> 📌 **核心认知**：**节点有延迟 ≠ 代理链路完整可用。** 详细原理可参考：[《机场节点延迟低但速度慢是什么原因？》](/issues/low-ping-slow-speed-reasons/)。

## 三、核心 7 步系统排查与精准修复法

请按照由底层到高层的顺序逐一排查：

### 第一步：确认本地网络与裸网环境正常
在排查代理之前，必须先排除本地物理网络故障：
1. 完全退出 Clash 客户端（确保任务栏无后台图标）；
2. 打开浏览器访问国内网站（如 `www.baidu.com` 或 `www.bilibili.com`）；
3. **判定结果**：
   - 如果国内网站也打不开 ➔ 说明是本地路由器、光猫欠费或 Wi-Fi 断网，先修复本地网络；
   - 如果国内网站秒开，但打开 Clash 后无法访问外网 ➔ 确认问题出在代理层，进入第二步。

---

### 第二步：不要只试一个节点，进行跨大区交叉测试
不要一遇到卡顿就断定整个机场故障：
1. 依次点击切换 **香港 01 ➔ 日本 01 ➔ 新加坡 01 ➔ 美国 01**；
2. **判定结果**：
   - **仅某一个节点打不开** ➔ 该服务器机房临时维护或正在重启，切换备用节点即可；
   - **所有香港节点全军覆没，但日本/美西正常** ➔ 亚太海缆故障或香港中转机房入口突发割接；
   - **所有地区全部节点同时无法上网** ➔ 说明是本地配置、系统代理或订阅源失效，进入第三步。

---

### 第三步：检查“系统代理 (System Proxy)”开关是否真正生效
这是导致“有节点却没网”最常见的高发原因（占 40% 以上）：

```
[正常路径] 浏览器 ──> 操作系统代理注册表 (127.0.0.1:7890) ──> Clash 内核 ──> 海外节点
[故障路径] 浏览器 ──(系统代理未生效/被篡改)──> 直接发往公网 (由于无代理直接被墙拦截报错)
```

1. **检查客户端开关**：确认客户端界面上的 **“系统代理 (System Proxy)”** 开关处于开启状态；
2. **检查 Windows 操作系统注册表**：
   - 打开 Windows 设置 ➔ “网络和 Internet” ➔ “代理”；
   - 检查“手动设置代理”是否已开启，地址是否为 `127.0.0.1`，端口是否与客户端监听端口一致（Clash Verge 默认通常为 `7897` 或 `7890`）；
3. **排查杀毒软件拦截**：检查 360、火绒、深信服等企业安全软件是否静默拦截了本地代理端口的写入。

---

### 第四步：检查分流模式（Rule vs Global vs Direct）
检查代理页面顶部的运行模式：

```
【Rule 规则模式】  ➔ 根据规则分流 (Google走代理，百度走直连) ➔ 日常推荐
【Global 全局模式】➔ 强制全部流量无条件走选定节点 ➔ 排查故障专用
【Direct 直连模式】➔ 强制所有流量不走代理直接连接 ➔ 误选此项会导致外网全部瘫痪
```

1. **排查误选 Direct**：如果误点成了 `Direct` 模式，所有外网请求直接裸连，必定无法打开；
2. **排查策略组节点选中状态**：在 `Rule` 模式下，展开 `PROXY`、`GLOBAL` 或 `节点选择` 策略组，**确保你已手动高亮选中了一个具体的海外节点**，而不是停留在 `DIRECT` 或 `REJECT` 上；
3. **临时切换 Global 交叉验证**：
   - 将模式临时切换为 `Global` 并选中一个可用节点；
   - 若 Global 下能打开 Google，但切回 Rule 后打不开 ➔ 说明是分流规则配置错误或规则集下载失败。参考：[《Clash Verge Rev 客户端完整配置教程》](/tutorials/clash-verge-rev/)。

---

### 第五步：排查 DNS 解析异常与系统时间不同步
DNS 与系统时间是两个最隐蔽的“断网杀手”：

#### 1. 系统时间精准同步（误差必须 < 60 秒）
现代安全协议（VLESS、Shadowsocks 2022、TLS 1.3）具备防重放攻击机制。如果你的电脑主板电池老化或系统时间与北京时间**相差超过 60 秒**，服务器会无条件拒绝握手！
- **修复方法**：右键点击 Windows 右下角时钟 ➔ “调整日期和时间” ➔ 点击 **“立即同步”**。

#### 2. 清理本地 DNS 缓存
在 Windows 中以管理员身份运行 CMD，输入以下命令刷新缓存：
```bash
ipconfig /flushdns
```

#### 3. 检查客户端 DNS 配置
若在客户端日志中看到大量 `DNS resolve failed` 或 `i/o timeout`，在设置中开启 `Fake-IP` 模式，并将上游 DNS 设置为高可用的 DoH 地址（如 `https://223.5.5.5/dns-query` 和 `https://1.1.1.1/dns-query`）。

---

### 第六步：如果开启了 TUN 模式，排查虚拟网卡与路由冲突
如果你启用了 TUN 模式，它会接管全局路由表：
1. **排查虚拟网卡服务状态**：在 Clash Verge Rev 设置中，确认 `Service Mode` 显示为绿色运行中；
2. **排查第三方网络工具冲突**：
   - 彻底退出电脑上正在运行的其他 VPN（如 Cisco AnyConnect、WireGuard、各大加速器）；
   - 关闭正在运行的 Docker Desktop、WSL 2 或 VMware 虚拟网卡；
3. **临时关闭 TUN 模式验证**：
   - 关闭 TUN 模式，仅保留“系统代理”；
   - 若关闭 TUN 后网络瞬间恢复 ➔ 证明 100% 是 TUN 虚拟网卡与系统路由或 DNS 发生了冲突。详细排查参考：[《Clash TUN 模式和系统代理有什么区别？》](/wiki/clash-tun-mode-vs-system-proxy/)。

---

### 第七步：更新机场订阅、检查配置文件与刷新内核
如果前六步均未解决，说明配置文件或节点信息已陈旧失效：
1. **右键强制更新订阅**：在“订阅 / 配置”页面，右键点击机场订阅选择 **“更新 (Update)”**，拉取服务商最新的节点 IP 与端口；
2. **检查套餐额度与到期时间**：登录机场官网后台，确认套餐是否已欠费逾期或当月流量已用尽；
3. **重启代理内核**：在客户端设置中点击“重启内核（Restart Core）”，重新加载 Mihomo 引擎。

## 四、核心排查总表：故障现象、可能原因与处理方向

| 常见故障现象 | 最可能的核心原因 | 优先排查与修复方向 |
| :--- | :--- | :--- |
| **所有节点有绿色延迟，但打不开 Google** | 系统代理未生效 / DNS 解析死锁 | 检查 Windows 系统代理设置（端口是否为 7890/7897），刷新 DNS 缓存 |
| **仅单个节点显示 Timeout，其他正常** | 单台海外服务器例行维护或机房重启 | 切换到同机场的其他备用节点 |
| **所有节点全部同时显示 Timeout / 红线** | 订阅已过期 / 机场更换入口 / 本地断网 | 先测本地裸网，登录官网检查套餐并强制更新订阅 |
| **Global 全局模式能用，但 Rule 模式失效** | 分流规则文件损坏 / 策略组停在 Direct | 在策略组中重新选定节点，更新 Rule Provider 规则集 |
| **一开启 TUN 模式整台电脑立刻断网** | 虚拟网卡服务未安装 / 路由冲突 / DNS 异常 | 安装 Service Mode，关闭其他 VPN，将 TUN Stack 改为 Mixed |
| **浏览器正常，但终端/游戏/某软件连不上** | 软件不遵循系统代理 / 需要 UDP 转发 | 开启 TUN 模式，或在软件内部手动配置 HTTP 代理 |
| **国内网页能打开，所有国外网站无法打开** | 代理节点失效 / 策略组未选择节点 | 切换节点，检查系统时间是否同步（误差需 < 60 秒） |
| **手机连接同一个机场正常，电脑却连不上** | 电脑端防火墙拦截 / 系统代理注册表损坏 | 检查电脑杀毒软件网络过滤，重置 Windows 网络栈 |
| **退出 Clash 后整个电脑完全连不上网** | 客户端异常退出导致系统代理未自动关闭 | 重新打开 Clash 正常关闭代理，或手动在系统设置中关闭代理 |

## 五、代理系统核心模块职责与出错表现对照表

| 核心模块 | 在代理链路中负责什么 | 一旦该模块出错后的典型表现 |
| :--- | :--- | :--- |
| **节点服务器 (Node)** | 提供海外网络出口与流量落地转发 | 测速报 Timeout，连接中断，无法建立 TCP 握手 |
| **系统代理 (System Proxy)** | 将操作系统的应用层 HTTP 流量引入 Clash | Clash 界面显示正常但所有浏览器均走直连被墙 |
| **分流规则 (Rule Engine)** | 决定不同域名的流量走向（Proxy / Direct / Reject） | 国内网站绕行变慢，或国外网站误走直连打不开 |
| **内置 DNS 模块** | 负责域名到 IP 的解析与防污染（Fake-IP） | 输 IP 能通但输域名全网报错，网页无限转圈 |
| **TUN 虚拟网卡** | 在 Layer 3 网络层强制截获所有底层数据包 | 开启后全盘断网、虚拟网卡报错、路由死锁 |
| **订阅源 (Subscription)** | 从服务商服务器获取最新的节点连接参数 | 节点配置过期失效、连接认证被服务端拒绝 |

## 六、如何精准区分“本地客户端问题”还是“机场服务端问题”？

很多用户一遇到网络断开就认定是服务商跑路，按照下表即可客观界定责任边界：

### 客户端问题 vs 机场服务端问题对照表

| 判定维度 | 🟢 极大概率是【本地客户端/电脑问题】 | 🔴 极大概率是【机场服务端问题】 |
| :--- | :--- | :--- |
| **多设备对比** | 手机连接相同 Wi-Fi 和订阅能正常上网，仅电脑不行 | 手机、电脑、平板使用该订阅全部同时无法上网 |
| **跨客户端对比** | Clash Verge 不行，但切换到 v2rayN 或小火箭能正常使用 | 换用任何客户端均显示全部节点 Timeout |
| **模式切换验证** | 切换到 Global 全局模式后网络瞬间恢复正常 | 无论是 Rule 还是 Global 模式均全盘超时 |
| **节点范围表现** | 仅部分节点或特定协议出现异常，大部分节点正常 | **全部国家、全部地区、所有节点在同一时刻全部爆红** |
| **订阅更新反馈** | 客户端内右键点击“更新订阅”秒级成功下载新配置 | 点击更新订阅直接提示 `Network Error` 或 `404/500` |
| **官方渠道状态** | 官网访问畅通，公告频道无异常 | 官网打不开、官方 Telegram 频道发布了机房断网抢修通告 |

## 七、节点异常范围判定法则：单节点 vs 单地区 vs 全局异常

| 异常范围 | 现象特征 | 最可能的原因 | 正确应对方案 |
| :--- | :--- | :--- | :--- |
| **单节点异常** | 列表中仅 `香港 01` 超时，`香港 02~05` 均正常 | 单台宿主机机房维护或进程崩溃 | 切换到同地区其他数字节点即可 |
| **单地区异常** | 所有 `香港` 节点全部超时，但 `日本/美国` 正常 | 对应区域的海缆故障或香港中转入口割接 | 临时分流至日本或新加坡节点 |
| **全部节点异常** | 整个订阅内所有国家节点同时全部红线超时 | 套餐欠费、订阅配置过期或服务商全线故障 | 1. 登录官网查套餐；2. 更新订阅；3. 查公告 |

## 八、为什么“卸载重装 Clash”通常不是首选解决方案？

许多新手一遇到打不开网页，第一反应就是卸载客户端再重新下载安装。**这通常是徒劳的：**

```
遇到问题 ──> 卸载重装软件 ──> 重新导入相同错误配置 ──> 依然存在同样故障 (浪费大量时间)
```

**为什么重装很难解决问题？**
1. 如果根因是**系统时间不同步、DNS 污染、机场节点失效或系统代理注册表冲突**，重新安装一个全新的客户端依然会继承操作系统的错误环境；
2. 卸载重装反而会丢失原有的分流规则自定义设置和代理组排序。
**正确的策略永远是：按照 7 步法分层定位问题根源，精准修复对应的设置项。**

## 九、如何查看与读懂 Mihomo / Clash 内核日志？

当界面无法直观看出问题时，日志是排查故障的最强武器。
在 Clash Verge Rev 左侧点击 **“日志 (Logs)”**，重点观察以下几类错误关键词：

```
[关键词 1: DNS Error / i/o timeout] ──> 内置 DNS 无法连通上游服务器 ➔ 检查 DNS 配置
[关键词 2: Handshake failed / certificate] ──> TLS 握手失败 ➔ 100% 是系统时间未同步
[关键词 3: Connect to proxy failed] ──> 节点服务器拒绝连接 ➔ 该节点已下线或端口失效
[关键词 4: Rule match: DIRECT] ──> 该请求命中了直连规则 ➔ 检查分流规则集
[关键词 5: TUN route create error] ──> 虚拟网卡路由创建失败 ➔ 检查管理员权限与服务模式
```

## 十、高频常见问题解答（FAQ）

### Q1：为什么 Clash 节点测速全部显示 Timeout（超时）？
**答**：首先确认电脑不开代理时能否正常访问国内网页。如果本地网络正常，请在客户端中执行“更新订阅”；若更新报错，请登录机场官网确认套餐是否已到期，或查看官方公告是否有服务器集群迁移。

### Q2：为什么 Global 全局模式能上网，但切回 Rule 规则模式就打不开外网？
**答**：这说明节点与网络连接完全正常，故障出在**分流规则**上。最常见的原因是：1. 策略组（如 `PROXY` 组）里误选了 `DIRECT`；2. 本地规则集（Rule Provider）下载损坏，在设置中更新规则集即可解决。

### Q3：为什么电脑一开启 TUN 模式，所有网页全部断网？
**答**：这是虚拟网卡接管系统路由时发生了 DNS 死锁或路由冲突。请在设置中将 TUN 模式堆栈（Stack）切换为 `Mixed`，并确认没有同时开启其他商业 VPN 或虚拟机网卡。

### Q4：为什么手机连接同一个节点能用，电脑上却打不开？
**答**：既然手机能用，说明**机场服务端完全正常**。请重点检查电脑端的：1. Windows 系统代理是否被杀毒软件拦截；2. 电脑系统时间是否与北京时间同步；3. 浏览器是否安装了冲突的代理插件（如 SwitchyOmega）。

### Q5：为什么能正常打开网页，但命令行 Git Clone 和 Docker Pull 一直超时？
**答**：因为终端命令行程序默认不读取 Windows/macOS 图形界面的系统代理。在 Clash Verge Rev 中安装服务模式并开启 **TUN 模式**，即可全自动接管终端流量。

### Q6：退出 Clash 之后，电脑浏览器彻底连不上网了怎么恢复？
**答**：这是因为客户端非正常退出，未及时清理 Windows 代理注册表。打开 Windows 设置 ➔ “网络和 Internet” ➔ “代理” ➔ 手动将“使用代理服务器”开关切换为 **“关”** 即可瞬间恢复。

### Q7：什么是系统时间不同步？为什么它会导致断网？
**答**：所有基于 TLS 的加密连接都依赖证书有效期校验。如果你的电脑时间比标准时间慢几分钟，加密握手会被服务器判定为非法重放攻击并直接掐断。右键系统时钟点击“立即同步”即可解决。

### Q8：换了多个节点都无法上网，什么时候才说明是机场出了问题？
**答**：当你确认：1. 本地裸网正常；2. 系统代理与时间正常；3. 多个不同国家的全部节点均无法连通；4. 手机和电脑均失效。此时基本可以断定是服务商服务端发生了故障。参考：[《机场跑路前有哪些风险信号？》](/risk/airport-running-away-warning-signs/)。

## 总结与分层诊断法则

> **排查核心法则：自底向上，分层定位，拒绝盲目重装。**

遇到“有节点但无法上网”时，请始终牢记排查顺序：
1. **先看本地** ➔ 本地裸网是否通畅、系统时间是否精准同步；
2. **再看接入** ➔ 系统代理开关是否生效、TUN 虚拟网卡是否冲突；
3. **后看分流** ➔ 策略组是否选中节点、内置 DNS 是否正常解析；
4. **终看服务** ➔ 订阅是否更新、官方是否有网络割接公告。
