## 二、URL 核心架构与 8 大意图命名空间

整站严禁所有内容平铺在单一目录下，必须严格隔离为 8 大意图空间：

```text
/ (根域)
├── recommend/     ➔ [商业推荐空间] 年度综合大榜、便宜机场推荐、AI 专线推荐
├── reviews/       ➔ [品牌评测空间] 单一品牌实体全景评测、价格、节点、线路
├── compare/       ➔ [对比选型空间] 品牌 1 对 1 深度横评、替代方案选型矩阵
├── tutorials/     ➔ [操作教程空间] Clash Verge Rev、Shadowrocket 客户端配置手册
├── issues/        ➔ [故障诊断空间] 连上有节点无网、Timeout 超时、晚高峰卡顿排障
├── protocols/     ➔ [协议专线空间] IEPL、IPLC、VLESS-Reality、Hysteria 2 底层原理
├── wiki/          ➔ [知识百科空间] Clash 概念、机场与 VPN 区别、Mihomo 内核区别
└── risk/          ➔ [风险数据库] 跑路预警信号、安全隐私评估、服务状态核验
```

## 三、Anti-AI URL 命名与安全准则（红线规范）

### 1. 严格禁止项（Blacklist Patterns）
- ❌ **严禁机械数字编号**：禁止 `/article/001/`、`/post/1002/`、`/page-003/` 等机器批量生成特征；
- ❌ **严禁暴露时间目录**：禁止 `/2026/08/article/`、`/2026-airport-review/` 等时间路径；
- ❌ **严禁关键词无限堆叠**：禁止 `/best-cheap-fast-stable-airport-2026/`，每个 slug 控制在 2~4 个核心英文单词；
- ❌ **严禁超过 3 级目录深度**：最大允许 `domain.com/category/sub-category/slug/`，严禁 4 级及以上过深结构；
- ❌ **严禁使用下划线或非英文字符**：一律使用纯小写字母 `a-z` 与短横线 `-`。

## 四、100 分制 SEO 页面价值评分系统

在为新关键词立项建页前，系统依据以下权重进行严格评分打分：

| 评估维度 | 权重分值 | 评估标准与打分细则 |
| :--- | :---: | :--- |
| **搜索需求量 (Search Volume)** | **30 分** | 月搜索指数与全网长尾覆盖广度（高：25-30，中：18-24，长尾：10-17） |
| **商业转化价值 (Commercial Value)** | **25 分** | 处于决策与购买漏斗阶段（直接买：22-25，对比选型：18-21，纯科普：10-17） |
| **长期资产寿命 (Longevity)** | **20 分** | 是否具备 3~5 年以上长期搜索复利（长期常青：18-20，阶段性：10-17） |
| **竞争与突围难度 (KD Score)** | **15 分** | 竞品弱度与本站 E-E-A-T 突围概率（易突破：13-15，中等：9-12，极难：1-8） |
| **内链拓扑价值 (Link Equity)** | **10 分** | 是否承担 Topic Cluster 中枢或桥接作用（核心枢纽：9-10，普通叶子：5-8） |

### 优先级输出档位：
- 🏆 **A 级 (P0: $\ge 88$ 分)**：核心高商业价值与高意图搜索词，**立即排期生产**；
- 🥈 **B 级 (P1: $75 \sim 87$ 分)**：支撑型专题与操作教程，**按计划批量建站**；
- 🥉 **C 级 (P2: $< 75$ 分)**：长尾补充与边缘词，**后续按需补充**。

## 六、全站网状内链拓扑体系（Link Equity Routing）

```
                     ┌───────────────────────────────┐
                     │ 核心商业天梯 Pillar [/recommend/]│
                     └───────────────┬───────────────┘
                                     │ (向下分流 / 向上回流)
                                     ▼
                     ┌───────────────────────────────┐
                     │ 品牌全景评测 Hub [/reviews/]  │
                     └───────┬───────────────┬───────┘
                             │               │ (横向互联)
                 (自上而下)   │               ▼
                             │    ┌───────────────────────────────┐
                             │    │ 1对1对比 / 替代 [/compare/]   │
                             │    └───────────────┬───────────────┘
                             ▼                    │ (商业桥接)
        ┌───────────────────────────────┐         ▼
        │ 客户端实操教程 [/tutorials/]   │ ◄───────┘
        └───────────────┬───────────────┘
                        │ (横向关联)
                        ▼
        ┌───────────────────────────────┐
        │ 故障诊断与排查 [/issues/]      │ ───(排障无效)───► [直推稳定专线光速云]
        └───────────────────────────────┘
```

1. **父子链（Vertical Flow）**：叶子页面必链回所属 Pillar；Pillar 必索引全部 Spokes；
2. **同级链（Lateral Flow）**：同一品牌或主题下的页面（如龙猫云线路 ➔ 龙猫云节点 ➔ 龙猫云替代）必须形成闭环互链；
3. **商业桥接（Commercial Bridges）**：排障与风险文章在文末必须给出“换用高稳定专线”的转化桥梁。

## 七、自动化前置审计与 CI/CD 质量门禁

在任何新文章合入发布前，必须运行：
```bash
node scripts/audit-urls.mjs
```

确保无 URL 重复竞争、无不合规字符、无目录超深、无 AI 编号特征，且全量 301 映射在 `astro.config.mjs` 中就绪。
